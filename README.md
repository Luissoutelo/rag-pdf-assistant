# RAG PDF Assistant

A question-answering system for PDF documents, built with RAG (Retrieval-Augmented Generation). It lets you ask natural language questions about the content of a PDF and get answers generated by an LLM, based only on the relevant context found in the document.

## How it works

1. **PDF Loading** — the document is read and converted into text
2. **Chunking** — the text is split into smaller pieces, with overlap between them to preserve context
3. **Embeddings** — each chunk is transformed into a numeric vector that represents its meaning, using the `all-MiniLM-L6-v2` model
4. **Vector Store** — the vectors are stored in a vector database (Chroma) for fast retrieval
5. **Similarity Search** — when a question is asked, the system finds the most relevant chunks by semantic similarity
6. **Answer Generation** — the retrieved context is sent, along with the question, to the Gemini model, which generates the final answer

## Stack

- **Python**
- **LangChain** — RAG pipeline orchestration
- **FastAPI** — API to serve the system over HTTP
- **ChromaDB** — vector database
- **Sentence Transformers** — embedding generation
- **Google Gemini API** — natural language answer generation

## How to run

1. Clone the repository
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Create a `.env` file in the project root with your Gemini API key:
   ```
   GEMINI_API_KEY=your_key_here
   ```
4. Place your PDF in the project folder and adjust the path in the code
5. Run the server:
   ```bash
   uvicorn main:app --reload
   ```
6. Go to `http://127.0.0.1:8000/docs` to test the API interactively

## Usage example

```
GET /question?question=what are the phases of the deal pipeline?
```

```json
{
  "answer": "The phases of the deal pipeline are: Qualification, Needs Analysis, Proposal Presented, Negotiation, Closed Won, Closed Lost"
}
```

## Notes

This project was built in two stages: first implemented manually (chunking, embeddings, and similarity search written from scratch, without frameworks) to understand the fundamentals of a RAG system, and then rebuilt with LangChain for comparison and production use.
